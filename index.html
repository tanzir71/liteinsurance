06 / FAQ

Questions an evaluator will ask before uploading a real CSV.

Docs →GitHub →

Does LiteInsurance send policyholder data to a cloud service?01

No. The production app is a PHP file backed by SQLite on your server. Imported CSV data stays in your hosting account unless you export it.

What are the server requirements?02

PHP 8.1 or newer (8.3 recommended) with PDO SQLite enabled. The default setup is designed for shared hosting and cPanel-style environments.

Can I try it before deploying PHP?03

Yes. The no-install demo starts with a deterministic 200-policy dataset, then lets you replace it with a local policyholder CSV, edit custom field cells, and build risk rules visually or as JSON for dashboards, segments, and campaign math.

Is this a full agency management system?04

No. LiteInsurance focuses on one slice: importing policyholder exports, cleaning them, scoring LTV and risk, working renewals, building consent-aware lists, and simulating outreach.

What happens with missing CSV fields?05

Mapped numeric fields use mean imputation; mapped categorical fields use mode or defaults. Unmapped columns are retained as custom fields, and LTV/risk scoring stays blank or Unknown until the required scoring inputs are mapped.

Can my CSV have custom fields?06

Yes. The importer uses Record ID and optional Display name mapping, while custom CSV fields preserved locally can be viewed, exported, and referenced from rules or segments with custom.field_key.

How do risk rules work?07

Rules use the same conditions-and-actions format whether you edit them in the visual builder or the plain JSON editor. Matching rules can set a risk tier, adjust confidence, and add tags for segment logic.
