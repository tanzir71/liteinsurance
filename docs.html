Deploy to shared hosting

Upload liteinsurance.php into public_html/, ensure PHP 8.1+ (8.3 recommended) and PDO SQLite are enabled, then visit /liteinsurance.php. The first registered user becomes the admin. Settings includes a Setup doctor for PHP, SQLite, paths, upload limits, cron token, and webroot storage checks.

public_html/
  liteinsurance.php
  .env             # optional

Visit: https://YOURDOMAIN/liteinsurance.php
Register first user -> Settings -> Setup doctor -> Import -> Preview -> Confirm import
DOC / 02

Run locally

The app has no build step. Use PHP's built-in server from the repository root. Upload the optional fonts/ folder next to the PHP file to use the bundled Inter typeface; without it the system font stack is used. No third-party requests either way.

php -S 127.0.0.1:8000
open http://127.0.0.1:8000/liteinsurance.php

DOC / 05

Risk rules

Rules are priority-ordered conditions and actions. They run highest priority first: the first matching rule that sets a tier wins, tags and score deltas accumulate, and "stop": true ends evaluation. Every policy stores which rules matched, so the Book panel can explain its tier, LTV and confidence. The app provides a visual builder for common field/operator/value rules and a plain JSON editor for nested groups or advanced edits. A matching rule can set risk_tier, adjust score, and add a tag. Supported leaf operators include =, !=, >, <, >=, <=, in, contains, and regex.

{
  "logic": "AND",
  "conditions": [
    { "field": "age", "op": ">=", "value": 60 },
    { "field": "tenure_months", "op": "<", "value": 12 }
  ],
  "actions": {
    "set_risk_tier": "High",
    "score_delta": 20,
    "add_tag": "senior_short_tenure"
  }
}
DOC / 06

Renewals and consent

Map an expiration (or effective) date and Today shows a renewal worklist; the Renewals board puts each open renewal in the column for its next step on the 120/90/75/45/30/15-day cadence (flag and prioritise, update exposures, remarket decision, compare quotes, present to client, bind), with its status (not started, contacted, quoted, remarketing, renewed, lost), owner and premium change on the card. Change the cadence in Settings and the columns follow it. Per-channel consent (email, SMS, calls) and opt-outs are stored on each policy; call lists, list exports and campaign reach only include consented, not-opted-out records. Paste a suppression list in Settings to opt people out in bulk. This is tooling, not legal advice: confirm the consent rules for your market (for example TCPA in the US).

Today -> Renewals board -> Call list CSV / Calendar (.ics)
Book -> open a policy -> log contact, update consent, see why it scored
DOC / 07

Lists, segments and exports

Lists (segments) combine selected rule IDs with a validated WHERE-style filter, written for you by a plain-language builder with a live, consent-aware count. Allowed fields include core fields, renewal fields such as days_to_expiry, renewal_status and policies_in_household, consent fields, plus custom fields using custom.field_key. CSV export is protected by a session token, filtered by channel consent, and appends enabled custom fields.

risk_tier = 'High' AND ltv_estimate > 7000
custom.renewal_probability >= 0.7 AND confidence_score >= 80
days_to_expiry >= 0 AND days_to_expiry <= 90 AND consent_phone = 1
DOC / 08

Security model

Web controls

CSRF on POST, session hardening, idle timeout, rate limits, security headers, optional TOTP two-step sign-in (admins can require it), and invite-only registration by default.

csrf_token

Data controls

PII is masked in list views; revealing a name or contact detail is audited. Uploads are randomized and blocked from direct browsing when possible. Settings shows a data inventory, exports the audit log, applies retention rules (staged uploads, audit log, contact history, long-expired policies), erases a person on request, or wipes all policy data.

mask_name
DOC / 09

Operations

Back up the SQLite database, rotate CRON_TOKEN, and run cron daily to recompute LTV, risk tiers and list sizes (rules that use days_to_expiry need it).

php /home/USER/public_html/liteinsurance.php action=cron_jobs cron_token=YOUR_TOKEN
